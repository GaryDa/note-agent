# note-agent

讀一個資料夾裡的零碎 `.txt` 筆記，由 agent 自己決定要分成幾類，把每份筆記歸到一類，每類輸出一個 Markdown 檔。

這是練習專案：agent loop 用 PHP 自己寫，不用 Tool Runner 或框架。學習計畫見 `~/MyProject/AgentDev101/practice-note-classifier.md`。

## 為什麼要用 agent

分類數量和分類名稱事先不知道，要讀過內容才能決定；讀到後面也可能要調整前面的想法。這些步驟沒辦法事先寫死，所以交給 agent。

固定的部分仍然用程式處理：列出檔案、讀檔、寫檔、檢查結果。模型只負責判斷。

## 用法（預定）

```bash
php bin/classify.php <筆記資料夾>      # 例：php bin/classify.php examples/notes
```

## 輸入

- 指定資料夾第一層的 `.txt` 檔，檔名可以是中文。不讀子資料夾，其他副檔名一律忽略。
- 檔案編碼是 UTF-8。
- 筆記數量至少 2 份、最多 50 份；超出範圍時直接結束並回報錯誤，不呼叫模型。
- 單一筆記超過 8,000 字時，讀取工具只回傳前 8,000 字，並告訴模型內容被截斷。

## 輸出

每個分類一個檔案，寫在 `out/` 底下，檔名是分類名稱（去掉 `/ \ : * ? " < > |` 和開頭的 `.`，最長 40 字）加上 `.md`：

```markdown
# PHP 環境設定

- php-ini設定.txt：說明靜態版 PHP 要用 PHPRC 指定 php.ini
- composer安裝.txt：Composer 的安裝與驗證步驟
```

- 第一行是 `# 分類名稱`。
- 之後每份筆記一行：`- 檔名：一句理由`，檔名要跟原始檔名完全相同。
- 每次執行前先清空 `out/`，結果只反映這一次的分類。

## 完成條件

一次執行同時符合以下全部條件，才算成功。這些條件之後會直接寫成 eval（`bin/eval.php`）的檢查項目。

| # | 條件 | 怎麼檢查 |
|---|---|---|
| 1 | 每份筆記**剛好**出現在一個分類裡，不漏也不重複 | 收集所有分類檔裡的檔名，跟輸入資料夾的 `.txt` 清單比對 |
| 2 | 分類數量介於 2 和 6 之間，而且不超過筆記數量 | 數 `out/*.md` 的檔案數 |
| 3 | 每個分類至少有 1 份筆記 | 每個分類檔至少有一行 `- ` |
| 4 | 每份筆記都附上理由，理由不是空的 | 每行 `：` 後面有文字 |
| 5 | 輸出格式符合上面的規格 | 第一行是 `# `，其餘是 `- 檔名：理由` |
| 6 | 沒有修改輸入資料夾，也沒有寫入 `out/` 以外的地方 | 執行前後比對輸入檔案的 sha256 |
| 7 | 在上限內完成：最多 15 回合、單次成本不超過 US$0.10 | 讀 run log |

「分類合不合理」沒辦法用程式判斷，先不列入自動檢查；eval 時人工抽看，之後再考慮用 LLM judge。

## 不做什麼

- 一份筆記只歸一類，不做多重標籤。
- 不修改、不搬移、不刪除原始筆記。
- 不讀子資料夾，不上網查資料。
- 不記得上次的分類結果，每次都重新分類（「重新分類模式」是階段 3 的新功能）。

## 執行限制

| 項目 | 值 | 超過時 |
|---|---|---|
| 模型 | `claude-haiku-5-5`（開發、測試） | — |
| 最多回合數 | 15 | 停止，回報失敗，保留已寫出的檔案供除錯 |
| 單次成本上限 | US$0.10（依 `usage` 累計） | 同上 |
| 筆記數量 | 2–50 份 | 不呼叫模型，直接回報錯誤 |

## 結束碼

| 碼 | 意義 |
|---|---|
| 0 | 成功，完成條件 1–6 都通過 |
| 1 | 執行失敗：超過回合或成本上限、API 錯誤、模型拒絕 |
| 2 | 輸入錯誤：資料夾不存在、筆記數量不在範圍內 |
| 3 | agent 跑完了，但輸出沒有通過完成條件檢查 |

## 範例資料

`examples/notes/` 有 8 份範例筆記，大致是三個主題（PHP 環境、agent 概念、生活雜事），另外有一份「今晚待辦」故意寫得模稜兩可，可以歸到 agent 也可以歸到生活。用來觀察 agent 怎麼處理邊界情況。

你自己的真實筆記請放在 `notes/`，這個資料夾在 `.gitignore` 裡，不會進版控。
